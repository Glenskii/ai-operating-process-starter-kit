# Routine: Public Claim Readiness

Use before publishing a README, article, case study, release post, sales page, or architecture explanation.

1. State the claim in one sentence.
2. Classify it: designed control, local verification, live verification, or unverified assumption.
3. Check relevant boundaries: stale state, approvals, interrupted work, concurrency, context cost, security, rollback, and syntax integrity.
4. Record evidence, residual risks, and verification gaps.
5. Rewrite the copy to match the evidence.

Avoid claims such as flawless, airtight, fully autonomous, always safe, or prevents every failure unless evidence truly proves them.
